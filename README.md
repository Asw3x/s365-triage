# s365-triage

Разбирает скоуп программ bug bounty из их текстовых описаний и ранжирует программы по тому,
насколько в них вообще имеет смысл заходить.

## Зачем

Программ больше сотни. Выбор «куда вложить вечер» обычно делается по максимальной выплате
в карточке — а это худший из доступных критериев: максимум платят за RCE, которого там нет,
зато доля принятых отчётов 12%, а первый ответ приходит через две недели.

Инструмент считает то, что влияет на исход: долю принятых отчётов, ширину скоупа и отдельно
количество wildcard-доменов, дату последнего принятого отчёта (программа жива или это витрина),
время первого ответа, рейтинг.

## Установка

Зависимостей нет, нужен Python 3.10+.

```bash
git clone https://github.com/Asw3x/s365-triage.git
cd s365-triage
```

## Использование

```bash
python3 -m s365 catalog.json                 # таблица, топ-25 по баллу
python3 -m s365 catalog.json -t risks        # программы с условиями «риски/сценарии»
python3 -m s365 catalog.json -n 0            # все программы
python3 -m s365 catalog.json --scope shop    # разобранный скоуп одной программы
python3 -m s365 catalog.json --json          # машинно-читаемый вывод
python3 -m s365 catalog.json -x vendor1 -x vendor2
```

## Каталог

Инструмент **не ходит в сеть** и работает с локальным JSON-файлом: список программ либо объект
с полем `items` / `results` / `programs`. Выгрузку делаешь сам — из того источника и с той
частотой, которые допускает площадка. Проверь её правила автоматического сбора, прежде чем
что-то автоматизировать.

Минимальный ожидаемый формат одной записи:

```json
{
  "slug": "shop", "name": "Shop", "status": "published", "finished": false,
  "terms": "only_vuln", "description": "<текст с описанием скоупа>",
  "rating": {"value": 4.5},
  "statistics": {
    "reportsAccepted": 40, "reportsTotal": 50,
    "avgFirstResponseSeconds": 36000, "lastAcceptedReportDate": "2026-10-01",
    "rewards": {"rub": {"max": 500000, "averageBounty": 25000}}
  }
}
```

Отсутствующие поля не ломают разбор — программа просто получает меньше баллов.

## Как разбирается скоуп

Описания пишут свободным текстом, где «в области действия» и «не принимаем» идут вперемешку.
Парсер режет описание на секции по заголовкам, определяет знак секции и каждой отдельной строки
по негативным маркерам (`не принима`, `вне области`, `исключ`, `out of scope` и подобным) и
раскладывает найденные домены на два списка. Домены площадок, магазинов приложений и
общеизвестных сайтов отфильтровываются как шум.

## Как считается балл

Веса собраны в одном месте — `s365/score.py`, словарь `WEIGHTS`. Они подобраны руками и спорны
по построению; смысл в том, чтобы их было удобно поменять под себя.

| слагаемое | вклад |
|---|---|
| максимальная выплата | 1 балл за каждые 100 000 |
| доля принятых отчётов | до 5 баллов |
| wildcard-домены | 1.5 за каждый, не больше 8 |
| всего доменов в скоупе | 1/6 за каждый, не больше 30 |
| рейтинг программы | половина значения |
| есть принятый отчёт за последние 180 дней | +3 |
| первый ответ быстрее 48 часов | +2 |

## Чего инструмент не делает

- Не сканирует цели и вообще к ним не обращается.
- Не решает за тебя: высокий балл означает «стоит посмотреть», а не «тут есть баг».
- Не заменяет чтение правил программы. Разбор скоупа — помощник, финальная сверка руками.
